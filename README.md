# ZOU — socle technique

Assistant d'information juridique sur le droit malgache. Next.js (App Router) sur Vercel, base Neon (Postgres), assistant Claude.

## Architecture

- `public/app.html` : l'interface ZOU (PWA), servie à `/` (réécriture dans `next.config.mjs`). Généré par `npm run pack:app` à partir de `src/artifact.html` : toute modification se fait dans `src/artifact.html`, puis `npm run pack:app`. Le même script écrit `public/sw.js` à partir de `scripts/sw.src.js` (ne pas modifier `public/sw.js` à la main) : liste des fichiers mis en cache dès l'installation (application, styles, script, polices, icônes, `public/offline.html`) et version du cache calculée sur leur contenu, si bien que chaque mise en ligne purge la précédente. Hors ligne, l'application s'ouvre depuis le cache dès le premier lancement ; une adresse jamais visitée affiche `public/offline.html` (« Pas de connexion », bouton « Ouvrir ZOU ») ; seule la page d'accueil remplace la copie locale, jamais une page d'erreur. Un bandeau fin « Hors ligne » (`#netBar`, événements `online`/`offline`) s'affiche sous l'en-tête et « Connexion rétablie » s'annonce au retour. Deux balises `theme-color` (clair et sombre, avec `media`) colorent la barre d'état avant tout script, puis suivent le thème choisi (`setThemeColor`). Au bas d'un plan, une invitation discrète propose d'installer ZOU (bouton sur Android, instructions Safari sur iPhone), refermable par « Plus tard » (mémorisé 30 jours, comme dans l'agenda) ; un bouton dans l'en-tête (`#headInstall`, juste avant la loupe) fait de même partout dans l'application, cette fois sans texte à côté — caché tant que le navigateur ne propose pas l'installation (`canInstall`), affiché dès l'événement `beforeinstallprompt`, masqué à nouveau après `appinstalled`. Le manifeste rouvre la fenêtre déjà ouverte depuis un raccourci (`launch_handler`). `app/layout.tsx` (viewport `cover`, `themeColor`, `appleWebApp`) et `app/not-found.tsx` ne servent qu'aux pages Next.js (page introuvable), aux couleurs et polices de l'application. CSS tactile : les styles `:hover` des commandes (lignes, onglets, puces, boutons) ne s'appliquent qu'aux pointeurs qui en sont capables (`@media (hover: hover)`), pour éviter la surbrillance qui reste collée au doigt sur un écran tactile ; `touch-action: manipulation` sur les commandes (pas de délai de 300 ms, pas de zoom au double-tap) ; les hauteurs liées à la fenêtre (feuille « Plus », panneau de liste sur ordinateur) utilisent `dvh` plutôt que `vh`, pour tenir compte de la barre d'adresse mobile plutôt que de la fenêtre figée. Navigation : la barre d'onglets (5 entrées : Accueil, Services, Espace, Pros, Plus) est toujours affichée, jamais démontée en changeant d'onglet ; aucune largeur n'affiche à la fois le menu « Services » de l'en-tête et la colonne latérale (pas de navigation dupliquée, cf. §3) ; les transitions d'écran durent 220 ms (dans la fourchette 150-250 ms), coupées si « moins de mouvement » ; une fois l'application installée (`navigator.standalone` ou `display-mode: standalone`), l'invitation à l'installer disparaît partout (bas d'un plan, menu « Plus »). Composants : pas de modale centrée (l'application n'en a jamais eu — la feuille « Plus » tenait déjà ce rôle) ; pas de rond qui tourne nulle part (l'assistant a déjà ses points qui pulsent). Menu contextuel (Coffre, Agenda) : un appui long (500 ms, sans bouger le doigt) sur une ligne ouvre une feuille nommée (`#rowMenu`, construite au moment de l'appui à partir des icônes déjà dans la ligne — gardées, pour le clavier et la souris) ; chaque entrée clique le vrai bouton correspondant, donc passe par le même répartiteur central et la même bannière « Annuler » ; rien sur une ligne sans action (Dossiers) ni pendant qu'elle est déjà ouverte par le glissement ci-dessus ; une vibration brève confirme l'ouverture, un tap en dehors ou « Échap » referme sans rien déclencher. Dossiers, Coffre et Agenda se tirent vers le bas pour actualiser (`.ptr` : bande qui grandit au doigt, pas de transform, ne touche pas l'`overflow` de `.main` ; « Tirer pour actualiser » → « Relâchez pour actualiser » au-delà de 64 px → actualisation (`runSync(true)`) ; réservé aux comptes connectés, rien chez un invité qui n'a rien à aller chercher sur le serveur ; pas de double geste si une feuille est déjà ouverte). Une vibration brève (`navigator.vibrate(10)`, silencieuse sur iPhone qui n'a pas l'API) confirme quatre instants : le seuil franchi en tirant pour actualiser, une ligne glissée au-delà du seuil (ci-dessous), une étape cochée, toutes les étapes d'un plan terminées. Dans le Coffre et l'Agenda, chaque ligne se glisse aussi vers la gauche pour révéler un bouton rouge « Supprimer » (seuil de 48 px, rendu à 96 px, une seule ligne ouverte à la fois, repliée par un tap ailleurs) : ce bouton ne porte pas son propre `data-act` (il clique le vrai bouton corbeille, déjà présent et gardé pour le clavier et la souris), si bien qu'il passe par le même répartiteur central et la même bannière « Annuler » que la suppression à l'icône. Finitions : les commandes à icône seule portent toutes un `aria-label` (HTML comme généré par JS) ; le focus clavier se voit partout (contour sur les commandes ; champs, cases et textarea utilisent un contour de bordure/halo plutôt qu'un contour de contour, tout aussi visible) ; les couleurs et la police dupliquées dans `public/offline.html` et `app/not-found.tsx` (deux pages hors de la coquille SPA) restent alignées sur celles de l'application, vérifié automatiquement plutôt que recopié à l'œil. `npm run pack:app` minifie maintenant le CSS et le JS avec esbuild (devDependency utilisée seulement à l'empaquetage : rien de nouveau dans ce que le navigateur charge) — script principal 1,27 Mo → 1,19 Mo, CSS 114 Ko → 95 Ko. Audit Lighthouse (serveur local, mobile, connexion lente simulée) : Accessibilité 100, Bonnes pratiques 100 sur l'accueil, `#display` et `offline.html` ; SEO 63, volontairement (`noindex` : l'application n'est pas destinée à être indexée) ; Performance 52 → 57 après minification — le reste tient à la latence réseau simulée (4G lente, 562 ms par aller-retour) contre un serveur de test local sans compression, pas à l'application elle-même (Vercel compresse automatiquement en production) ; l'« unused CSS/JS » que Lighthouse signale est pour l'essentiel voulu : tout le CSS et tout le JS de chaque domaine sont chargés d'un coup pour que l'application marche hors ligne dès le premier lancement (Phase 1), au prix d'un peu de code non utilisé sur un écran donné.
- Interface ↔ API (section « Serveur » de `src/artifact.html`) : au démarrage, `GET /api/health` dit ce qui est branché. Sans serveur ou sans base, l'interface reste en mode invité, comme avant. Avec l'IA, les questions vont à `/api/ask` (réponse, renvois [n], sources) ; sinon, comportement d'origine.
- `app/api/*` : routes d'API (Node). Aucune dépendance autre que `next`, `react`, `react-dom`, `@neondatabase/serverless`, `@vercel/blob` (Node ≥ 22.6).
- `lib/schema.ts` : schéma Postgres, appliqué par `POST /api/admin/migrate` ou `npm run db:migrate`.
- `lib/ingest.ts` : chargement des textes de loi (validation, découpage automatique en articles, remplacement atomique).
- `textes/` : les textes de loi, chargés automatiquement à chaque déploiement en production (voir `textes/README.md`).
- `lib/ask.ts` : recherche plein texte (français, accents pliés) dans `legal_chunks` — classement par nombre de mots de la question présents, puis pertinence corrigée de la longueur — puis appel à Claude avec citations obligatoires. Recherche par mots-clés seulement : une question formulée sans les mots du texte (« quel âge pour se marier ») trouve mal ; une recherche sémantique (embeddings) serait l'étape suivante.
- Parcours de vie (`src/artifact.html`, section « Parcours de vie ») : une question par écran, puis un plan personnalisé (verdict, dates limites calculées avec ajout à l'agenda, étapes à cocher, pièces à préparer, lieux, lettre pré-remplie, sources). Un parcours est décrit par des données (`defVie` : questions avec conditions, fonction `plan`). Affichage et lisibilité (page `#display`, accessible par « Plus » et le pied de page) : thème clair, sombre ou automatique (selon l'appareil), taille du texte (×1,15 ou ×1,3 : tous les `font-size` en px passent par `--fs`), contraste renforcé. Tout est défini par des jetons de couleur (`:root`, blocs `prefers-color-scheme: dark` et `data-theme="dark"`) : ne plus écrire de couleur en dur dans le CSS de l'interface (le sourire du logo passe lui aussi par `--smile`). Direction visuelle « institutionnel sobre » (inspirée de GOV.UK et du DSFR) : neutres sans teinte (sombre en gris `#161616`, pas en bleu nuit), titres en encre (`--trust` = couleur des titres et du logo), bleu marine réservé à ce qui se touche (`--accent` : boutons, liens, onglet actif), coins de 4 à 6 px, listes à filets fins plutôt que cartes encadrées (situations de vie, suites d'un plan), suggestions en pastilles pleines sans contour. L'accent (`--accent`) est un **bleu électrique** (`#0B63E8` en clair, `#4D9BFF` en sombre, sourire du logo en `--smile`) : il porte tout ce qui agit (bouton d'envoi, liens, onglet et élément de barre latérale actifs, focus, barre de progression, cases cochées) et teinte le verdict « à savoir » d'un plan (aplat `--accent-soft`, étiquette dans l'accent, sans bordure) ; le vert des statuts (« il reste N jours ») reste indépendant. Le logo est plus compact (76×35 px, 84×39 sur ordinateur) dans un en-tête de 56 px (60 sur ordinateur). Sur ordinateur, la barre de défilement est fine et discrète (curseur arrondi `--rule-strong`, plus foncé au survol), largeur réservée pour éviter tout saut. Animations légères (CSS + un peu de JS, sans bibliothèque), toutes coupées si l'appareil demande « moins de mouvement » : les blocs de l'accueil et du plan apparaissent en fondu quand ils entrent dans l'écran (`IntersectionObserver`, `reveal`), le nombre de jours restants monte jusqu'à sa valeur (`countUp`), la case cochée fait un petit ressort, la flèche des listes glisse de 2 px au survol, et l'assistant montre des points pendant la recherche puis la réponse en fondu. L'accueil est une « vitrine » : un dégradé animé (quatre taches de couleur floutées qui ondulent lentement, `IntersectionObserver` inutile ici — c'est du CSS, `#heroAura`) se tient derrière le héros, avec texte blanc, carte de question posée et, sur téléphone, en-tête translucide en haut (classe `at-top`, redevient opaque dès qu'on défile) ; un voile sombre garantit le contraste AA du texte blanc, validé en clair et en sombre par échantillonnage des pixels. Le dégradé est réservé à l'accueil : plans, formulaires et listes restent sobres. La barre d'état (theme-color) prend la couleur du haut du dégradé sur l'accueil. Les titres sont en Bricolage Grotesque (`--font-disp`, hébergée, licence SIL OFL, préchargée), le texte reste en Inter. Le dégradé se fige si l'appareil demande « moins de mouvement » et se met en pause quand l'onglet n'est pas visible. Petits plaisirs : quand toutes les étapes d'un plan sont cochées, une carte « Toutes les étapes sont faites » apparaît (coche dessinée et gerbe de confettis aux couleurs de l'accent, au moment où l'on coche la dernière case seulement ; gardée sans animation au rechargement, retirée si on décoche, avec un lien vers le coffre) ; les dates limites d'un plan sont résumées par une frise (aujourd'hui en bleu, dates dépassées en rouge, proches en orange, lointaines en vert, décrite pour les lecteurs d'écran, masquée à l'impression) ; les écrans vides (dossiers, coffre, agenda, recherche sans résultat) montrent une petite illustration au trait (`ART`, SVG en ligne, aux couleurs du thème, `cfg.art` dans les tableaux) ; l'écran Dossiers vide propose en plus 3 situations fréquentes à commencer directement (mêmes cartes que l'accueil) ; dans le Coffre, « Ajouter un document » et « Photographier » ont la même largeur ; dans la liste des Services, l'icône de type (calcul, parcours guidé, lettre…) se détache sur un fond neutre pour mieux scanner la liste. Tous les textes passent le seuil WCAG AA dans les quatre combinaisons (clair, sombre, avec ou sans contraste renforcé). Sur téléphone (moins de 1000 px), l'application se comporte comme une application native : écrans racines (un par onglet : `ROOTS`) et écrans empilés ; sur un écran empilé, l'en-tête montre le bouton retour (repris du bouton retour ou du fil d'Ariane de l'écran, masqués dans la page — réduit au chevron, le nom du parent reste dans le DOM pour les lecteurs d'écran sans réserver de place visuelle) et le titre de l'écran en vraie disposition flexible (pas de largeur figée) pour rester lisible même sur un nom de parcours long, qui apparaît quand le grand titre passe sous l'en-tête ; l'écran suivant glisse depuis la droite, le retour depuis la gauche, les onglets changent sans animation, rien ne bouge si l'appareil demande moins de mouvement ; l'écran qui part glisse lui aussi, dans l'autre sens (`ghostOut`) : un clone jetable (en-tête compris, identifiants retirés), posé par-dessus en position fixe puis retiré une fois l'animation finie, décalé du défilement en cours pour repartir d'où l'œil l'a laissé plutôt que de son propre haut — imite l'effet d'une vraie transition d'écran sans l'API View Transitions, dont le callback s'exécute de façon asynchrone (vérifié), incompatible avec show()/go() écrits partout dans l'application comme synchrones (essayé, abandonné pour cette raison : focus cassé sur le champ de question après un go("home") programmatique, entre autres) ; sur un écran empilé, un doigt posé dans les 24 derniers pixels du bord gauche et glissé vers la droite (comme iOS) fait suivre l'écran au doigt (ombre portée) et complète le retour au-delà de 80 px ou d'un flick rapide, sinon l'écran revient en place ; rien sur un écran racine (pas de retour), sur grand écran (le bouton « Retour » de l'en-tête n'existe qu'en dessous de 1000 px) ou si une feuille est ouverte par-dessus (pas de double geste) ; chaque onglet garde son dernier écran et sa position, toucher l'onglet actif revient à sa racine puis remonte en haut ; la feuille « Plus » a une poignée et se ferme en glissant vers le bas ; l'en-tête, la barre d'onglets, la feuille « Plus » et le menu contextuel sont en verre dépoli (fond translucide + flou, `backdrop-filter`, couleur dérivée de `--surface` par `color-mix` pour rester sur la même source que les jetons de thème) — le contenu défilé se devine derrière, comme sur iOS ; repli sur un fond plein et sans flou si l'appareil demande « réduire la transparence » ou si le contraste renforcé est actif (même mécanisme que le mode sombre), et l'en-tête de l'accueil en haut de page reste lui totalement transparent sans flou (voile dégradé déjà testé par ailleurs) ; pas de pied de page de site (ses liens et l'avertissement sont dans « Plus ») ; pas de surbrillance de toucher ni de sélection de texte sur les commandes. Sur tablette (768 à 1199 px), une colonne d'icônes à gauche remplace les onglets du bas et « Plus » s'ouvre en panneau à côté ; sur ordinateur (1200 px et plus), une barre latérale avec libellés (`#sideNav` : thèmes, Mon espace, aide, réglages, avec l'écran courant) remplace aussi le menu du haut. Sur ordinateur, Services et Dossiers passent en deux panneaux (`applySplit` : `SPLIT_BASE` à gauche, `SPLIT_DETAIL` à droite — guide, calcul, lettre, parcours, démarche) quand le détail est ouvert depuis la liste ; la ligne ouverte y est marquée, un seul panneau sous 1200 px. La police Inter 4 (graisse et taille optique) est servie par l'application (`public/assets/fonts/`, licence SIL OFL jointe, préchargée, en cache hors ligne) : plus aucun appel à Google Fonts, et la politique de sécurité n'autorise plus que `'self'` pour les polices et les styles. Claviers : touche « Envoyer » dans les champs de question et de connexion, « Rechercher » dans les recherches, « Suivant » dans les lettres, remplissage automatique du nom, de l'adresse et de la ville de la personne ; sur téléphone, la barre d'onglets s'efface pendant la saisie (retour différé de 250 ms pour que le toucher qui ferme le clavier atteigne son bouton). Les suppressions (date, document, exemples) et « Recommencer à zéro » ne demandent plus de confirmation : une bannière propose « Annuler » pendant 6 secondes (`toast(msg, { run })`, `undoable`), et la synchronisation attend la fin de ce délai (`undoUntil`) pour que rien ne soit effacé sur le serveur tant qu'on peut annuler. Écrans de démarrage iPhone en clair et en sombre (`public/icons/splash/`, liste dans `scripts/splash-sizes.mjs`, à régénérer avec `node scripts/make-splash.mjs` si le logo ou les fonds changent). Les réglages sont mémorisés sur l'appareil (`zou_prefs_v1`) et appliqués avant le premier affichage par `scripts/theme-init.js` (copié dans `public/assets/theme.<hash>.js` par `npm run pack:app`). L'impression reste claire quel que soit le thème. Chaque plan peut être imprimé ou enregistré en PDF (mise en page A4 dédiée construite dans `#printDoc`, le reste de l'écran masqué à l'impression : en-tête ZOU, verdict, tableau des dates limites, étapes avec cases à cocher reprenant ce qui est déjà fait, pièces, réponses, sources, puis la lettre type seule sur sa dernière page, sans pied de page ZOU) et partagé (feuille native du téléphone, sinon WhatsApp, e-mail ou copie du résumé ; aucune donnée personnelle dans le résumé). Les lettres s'impriment seules (champs vides en pointillés, zone de signature). Chaque plan affiche « Plan rédigé en … ; relecture par un juriste : à venir » : renseigner `VIE_REVIEW` (par identifiant de parcours) dans `src/artifact.html` quand un juriste a relu un plan. Les dates des 7 prochains jours apparaissent à l'accueil et en pastille sur l'onglet Espace, et sur l'icône de l'application installée (Badging API, `navigator.setAppBadge`/`clearAppBadge`, même compte, à jour dès qu'une date est ajoutée ou supprimée, silencieux si l'appareil ou le navigateur ne proposent pas l'API) ; l'invite d'installation du navigateur est interceptée (`beforeinstallprompt`) et proposée dans l'agenda et dans « Plus ». Les domaines sont regroupés en 5 thèmes (`GROUPS` dans `src/artifact.html` : Famille et papiers, Travail et protection, Logement et biens, Entreprise, Justice) pour l'accueil, le menu, la page Services (`#services.g-<thème>`) et le pied de page. Domaine « Famille » : naissance, jugement supplétif, mariage, séparation et divorce, décès et héritage, enfant en danger, nationalité. Domaine « Entreprise et commerce » (lois 2015-037, 99-018, 2003-036 et 2003-042) : bail commercial (renouvellement, congé, loyer, cession, résiliation), lancer son activité ou créer une société, comptes annuels et assemblée, entreprise en difficulté (cessation des paiements, règlement préventif), créance dans une faillite. Domaine « Copropriété et sûretés » (décret 50-1631 sur la copropriété, loi 2003-041 sur les sûretés, tous deux dans le recueil foncier) : copropriété (charges impayées, majorités de vote, syndic, titre), caution (avant de signer, réclamation, recours), hypothèque, gage, nantissement, fehivava et réserve de propriété. Domaine « Séjour des étrangers » (loi 62-006 sur l'immigration, décret 94-652, arrêté 8421/97 sur les visas, décret 98-352, Code du travail art. 61, textes présents dans le recueil `droits-civils`) : visa et séjour, travail d'un étranger, étranger et terre, refoulement et expulsion, réfugiés et apatrides. Les textes qui se contredisent (prorogation du visa de court séjour, article 11 en deux versions) sont signalés tels quels. Les montants fixés par décret (capital minimum…) et la procédure d'immatriculation ne figurent pas dans les textes chargés : les parcours le disent au lieu de les inventer. Proposés depuis l'accueil (« Qu'est-ce qui vous arrive ? »), les Services et l'assistant (mots-clés). Réponses et progression sauvegardées dans les dossiers du compte (`kind: vie`).
- Mode invité : l'interface fonctionne sans compte ; les données restent dans le navigateur. `POST /api/import` les rattache à un compte à la première connexion (idempotent).
- Synchronisation : une fois connecté, chaque enregistrement local part au serveur (création, modification, suppression), et l'état du compte est récupéré au démarrage, au retour de la connexion et au retour sur l'onglet. Démarche « Démissionner » et guides → `cases` ; agenda → `events` ; coffre → `documents` (métadonnées). Les exemples ne sont jamais envoyés. Effacer les données de l'appareil déconnecte d'abord, sans rien supprimer du compte.
- Fichiers du coffre : Vercel Blob en **accès privé** (`lib/blob.ts`). Envoi par `PUT /api/documents/:id/file` (corps brut, 4 Mo au plus, PDF / JPEG / PNG / WebP / HEIC / Word, 200 Mo par compte), téléchargement par `GET` (propriétaire seulement, toujours en pièce jointe), retrait par `DELETE`. Supprimer un document supprime son fichier. Aucune URL de fichier n'est jamais transmise au navigateur.
- Connexion : code à 6 chiffres envoyé par e-mail (Resend), session par cookie signé HttpOnly de 30 jours.
- Rappels : tâche planifiée quotidienne (`vercel.json`, 05:00 UTC = 08:00 à Antananarivo) → `/api/cron/reminders`.

## Variables d'environnement (`.env.example`)

| Variable | Rôle | Sans elle |
|---|---|---|
| `DATABASE_URL` | Neon (chaîne pooled) | API de données en 503, interface en mode invité |
| `AUTH_SECRET` (≥ 32 car.) | signature des sessions | connexion désactivée |
| `ANTHROPIC_API_KEY` | assistant | `/api/ask` en 503 |
| `RESEND_API_KEY`, `MAIL_FROM` | e-mails (codes, rappels, contacts) | codes non envoyés, rappels non partis |
| `ADMIN_TOKEN` (≥ 24 car.) | migrations, ingestion, vérification des pros | routes admin refusées |
| `CRON_SECRET` (≥ 16 car.) | protège la tâche de rappels | tâche refusée |
| `BLOB_STORE_ID` ou `BLOB_READ_WRITE_TOKEN` | fichiers du coffre : ajoutée par Vercel en reliant un magasin Blob (les magasins récents n'ajoutent que `BLOB_STORE_ID`, l'accès passant par le jeton OIDC que Vercel fournit à chaque requête) | seules les informations des documents sont sauvegardées |
| `SUPPORT_EMAIL` | destinataire du formulaire de contact | message enregistré, non transmis |
| `ZOU_DB_SETUP` | `auto` (défaut), `always` ou `off` : préparation de la base au déploiement | `auto` : production seulement |

## Mise en route

1. Créer le projet Vercel lié au dépôt, ajouter la base Neon (Marketplace Vercel → Neon : `DATABASE_URL` est renseignée automatiquement), créer un magasin Blob **en accès privé** (Storage → Blob) et le relier au projet (`BLOB_STORE_ID` ou `BLOB_READ_WRITE_TOKEN` est renseigné automatiquement), puis ajouter les autres variables ci-dessus.
2. Le schéma est appliqué automatiquement au déploiement (étape 3). Pour l'appliquer à la main, au choix :
   - depuis un poste : `npm install` puis `DATABASE_URL=… npm run db:migrate` (lit aussi `.env.local` / `.env`) ;
   - sur le site déployé : `curl -X POST https://<domaine>/api/admin/migrate -H "Authorization: Bearer $ADMIN_TOKEN"`.

   Les deux passent par `applyMigrations` (`lib/schema.ts`) et sont idempotents. `npm run db:sql` affiche le SQL sans l'exécuter.
3. Déposer les textes de loi dans `textes/` (`.txt`/`.md` découpés automatiquement, ou `.json` déjà découpé ; voir `textes/README.md`)
   et déployer. Le script `vercel-build` lance `scripts/setup-db.mjs` avant `next build` : migrations, puis chargement
   des textes nouveaux ou modifiés (un texte inchangé n'est pas réécrit, un texte modifié est remplacé en une transaction).
   Ignoré sans `DATABASE_URL` et sur les prévisualisations (`ZOU_DB_SETUP=always` pour les inclure, `off` pour tout désactiver) ;
   une erreur fait échouer le déploiement. À la main : `npm run db:ingest` (`-- --check` pour vérifier le découpage sans base,
   `-- --force` pour tout recharger). Toujours possible par l'API : `POST /api/admin/ingest` avec `{ source, title, chunks: [{ article, heading, text }] }`.
4. Vérifier : `GET /api/health`.

## Routes

Publiques : `GET /api/health`, `POST /api/ask`, `POST /api/feedback` (avis « ce plan vous a-t-il aidé ? » et signalement d'erreur, sans compte, 20 par heure et par adresse), `GET /api/pros`, `POST /api/pros/:id/contact`, `POST /api/contact`, `POST /api/auth/request|verify|logout`.
Connecté : `/api/me`, `/api/cases`, `/api/events`, `/api/documents`, `/api/import`, `/api/pros` (inscription), `/api/pros/me`.
Admin (jeton) : `/api/admin/migrate`, `/api/admin/ingest`, `/api/admin/pros`, `GET /api/admin/feedback?kind=erreur|avis` (retours sur les plans et statistiques par plan).

## Limites connues

- Fichiers : 4 Mo au plus (limite des fonctions Vercel ; au-delà, prévoir l'envoi direct du navigateur vers Blob). Un fichier ajouté n'est gardé qu'en mémoire jusqu'à son envoi : sans compte, ou si la page est rechargée avant l'envoi, seules ses informations restent, et le coffre propose « Joindre le fichier ».
- Rappels : seul l'e-mail est envoyé (les canaux WhatsApp/SMS ont été retirés de l'interface). Le partage de documents avec un professionnel n'existe pas encore : la demande de contact transmet un message.
- Synchronisation sans fusion fine : une modification locale non envoyée l'emporte sur le serveur ; sinon le serveur l'emporte. La démarche « Démissionner » d'un nouvel appareil remplace celle du compte si elle a déjà été commencée sur cet appareil avant la connexion.
- CSP : `style-src 'unsafe-inline'` reste nécessaire (attributs `style` de l'interface).
- La balise `noindex` de `app.html` est volontaire jusqu'au lancement.
